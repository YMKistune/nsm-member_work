## ผลตรวจเพิ่มเติมกราฟ (11 ต.ค. 2569)

เพิ่มกราฟโดยไม่แก้โครงสร้างฐานข้อมูลในหน้า: member_categories.php, section_data_page.php (ใช้ร่วมกับหน้า อพ./ออนไลน์/บูธ), outdoor_booth.php, member_active.php, member_museum_rights.php, member_lounge.php และ performance.php.

การตรวจที่ทำในสภาพแวดล้อมจัดทำไฟล์:
- รัน php -l กับไฟล์ PHP ทั้งชุดหลังแก้ไข
- ตรวจ syntax JavaScript ของ inline scripts ในไฟล์ที่แก้ไข โดยแทนค่า PHP echo เป็นค่ากลางสำหรับตรวจ syntax เท่านั้น
- ตรวจชื่อ canvas และการเรียก Chart.js ในหน้าที่เพิ่มกราฟ
- ไม่เปลี่ยน SQL schema

ข้อจำกัด: ยังไม่ได้รันกับฐานข้อมูล MariaDB ของผู้ใช้, ไม่ได้ทดสอบผลลัพธ์ของทุก query บนข้อมูลจริง และไม่ได้ทดสอบ browser rendering บน XAMPP. กราฟยอดสุทธิเป็นตัวเปรียบเทียบจากคอลัมน์ยอดสุทธิ ไม่ใช่การยืนยันสูตรรายได้ทางบัญชี. กราฟพิพิธภัณฑ์และ Lounge นับรายการ Excel ที่ตรงเงื่อนไข ไม่ใช่จำนวนครั้งใช้สิทธิ์จริง.


## ผลตรวจเพิ่มเติม: จัดหมวดหมู่แบบรวมกลุ่ม (11 ต.ค. 2569)

ปรับเฉพาะหน้า member_categories.php:
- แทนการเลือกสมาชิกทีละแถวด้วยการรวมรายการที่ยังไม่จัดหมวดตามช่องทางจำหน่าย, POS, สถานที่/กิจกรรม, กิจกรรม/Package และหมายเหตุ
- แสดงจำนวนสมาชิกต่อกลุ่ม พร้อมค่าที่ใช้ตัดสินใจและตัวอย่างสมาชิก/วันที่สมัคร
- เลือกได้หลายกลุ่มแล้วกำหนดหมวดปลายทางครั้งเดียวใน 3 หมวดหลัก
- ยังคงการตรวจฝั่งเซิร์ฟเวอร์ว่ารายการต้องอยู่ในปีงบประมาณที่เลือกและ source_section='unknown' เท่านั้น
- จำกัดรายการที่ส่งเปลี่ยนหมวดไม่เกิน 1,000 รายการต่อคำขอ และมีการยืนยันก่อนบันทึก
- ใช้ชื่อและวันที่สมาชิกเพื่อแสดงตัวอย่างเท่านั้น ไม่ใช้เป็นเกณฑ์แบ่งกลุ่ม
- ไม่มีการแก้ไขค่าคอลัมน์ต้นฉบับจาก Excel หรือเพิ่มหมวดหลักที่ 4

การตรวจที่ทำ:
- php -l ผ่าน 32 ไฟล์ PHP ในแพ็กเกจ
- ตรวจ syntax ของ inline JavaScript ใน member_categories.php ผ่าน หลังแทน PHP echo เป็นค่ากลางสำหรับตรวจ syntax
- ตรวจการส่งรายการที่เลือกจากกลุ่มผ่าน hidden row_ids[] และตรวจว่า server update เฉพาะ unknown ของ fiscal_year ที่ระบุ
- ยังไม่ได้ทดสอบการทำงานกับฐานข้อมูล MariaDB/XAMPP จริงหรือการแสดงผลในเบราว์เซอร์
- หน้าแสดงได้สูงสุด 5,000 รายการที่ยังไม่จัดหมวดต่อครั้งเพื่อจำกัดภาระการโหลด; หากมีมากกว่านี้จะมีคำเตือน


## ตรวจเพิ่มเติมปัญหา MariaDB error 1932 (12 ต.ค. 2569)

- ปรับ ensureExcelTables() ให้ตรวจจับ PDOException หมายเลข 1932 ที่เกี่ยวกับตาราง Excel และแสดงหน้าแจ้งเตือนพร้อมขั้นตอนปลอดภัย แทนการแสดง stack trace แบบเดิม
- เพิ่ม sql/diagnose_excel_import_tables.sql สำหรับตรวจ metadata/status ด้วยคำสั่งอ่านข้อมูลเท่านั้น และ FIX_EXCEL_IMPORT_TABLE_1932_TH.txt เป็นคู่มือภาษาไทย
- ไม่มีการใช้ DROP TABLE, TRUNCATE, DELETE หรือคำสั่งสร้าง/แก้โครงสร้างในไฟล์วินิจฉัย
- ข้อจำกัด: ไม่สามารถเชื่อมต่อฐานข้อมูล nsm_member ของผู้ใช้ได้ จึงยังไม่ยืนยันว่าตารางเสียหายจริง และยังไม่ได้ซ่อมฐานข้อมูล live; ต้องสำรองฐานข้อมูลและส่งผล SQL วินิจฉัยก่อนเลือกวิธีซ่อม
